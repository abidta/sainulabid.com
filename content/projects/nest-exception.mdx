If you've used NestJS, you know how pleasant its errors are. You write
`throw new NotFoundException('User not found')` anywhere in your code, and the
client gets a clean, predictable response:

```json
{ "statusCode": 404, "message": "User not found", "error": "Not Found" }
```

In a plain Express or Fastify app, that convenience is missing. Teams invent
their own error classes, and every project's error responses end up looking
slightly different.

It turns out NestJS's exception classes barely depend on the rest of the
framework. So I lifted them out. `nest-exception` packages NestJS's HTTP
exceptions as a small standalone library with no dependencies. The code is
MIT-licensed, and the original NestJS source is credited in every file.

## What you get

- **The full set of HTTP exceptions** — `BadRequestException`,
  `UnauthorizedException`, `ForbiddenException`, `NotFoundException`,
  `ConflictException`, `UnprocessableEntityException`,
  `ServiceUnavailableException` and more: 21 in all, plus the base
  `HttpException` for any other status code. (Yes, `ImATeapotException` is in
  there too.)
- **The same response shape NestJS uses**, so error bodies look the same across
  every service.
- **Error causes.** Pass `{ cause: originalError }` to keep the underlying
  error for your logs without sending it to the client.
- **Helper enums** like `HttpStatus`, so you can write `HttpStatus.CONFLICT`
  instead of a bare `409`.
- **TypeScript types** included.

## How to use it

Throw from wherever the problem is found, and handle every error in one place:

```js
const { HttpException, NotFoundException } = require('nest-exception')

app.get('/users/:id', async (req, res, next) => {
  const user = await findUser(req.params.id)
  if (!user) return next(new NotFoundException('User not found'))
  res.json(user)
})

// One error handler for the whole app
app.use((err, req, res, next) => {
  if (err instanceof HttpException) {
    return res.status(err.getStatus()).json(err.getResponse())
  }
  res.status(500).json({ statusCode: 500, message: 'Internal Server Error' })
})
```

Route handlers stay focused on the happy path, and the response format lives in
exactly one place.
